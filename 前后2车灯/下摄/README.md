# 下摄前后双车灯实例

本实例从 `instances_down/0801_下摄原始灰度信标草稿` 复制并做离线双车灯结构适配，仅供 BeaconImageAnalyzer 编译和回放，不修改 Air 固件、SPI 协议或车端代码。

算法 Build ID：`0x20261002`。

## 模式

- 默认是单车灯模式，保持来源实例的分类阈值、主目标选择和时序输出不变。
- 双车灯模式通过可选动态接口 `beacon_image_set_car_lamp_mode(2)` 启用。
- 复用来源实例已有的多候选收集结果，最多保留两个车灯轨迹；内部槽位不表示物理车头或车尾。
- 任一灯板单独可见时允许只输出一个；两个当前/预测车灯区域都会参与信标遮罩和最终互斥。

## 双灯配对约束

第二候选保持原分类阈值，并同时满足：

- 两灯角度差不超过 25°；
- 长度比不超过 2.5；
- 两个旋转框不重叠；
- 中心距离不超过较长灯板长度的 4 倍。

下摄参数比前后摄更宽，属于结构适配值。真实新结构下摄视频已用于当前严格配对阈值验收；后续如增加不同高度、角度或遮挡条件的视频，再继续分层复核。

## 车体连接遮罩

两块灯板配对成立后，算法取两个旋转灯板边界的 8 个角点构造凸包，将两灯之间的区域视为车体，不再允许输出信标。遮罩按 120 行预计算左右边界；下摄灰度候选扫描先做两次整数边界比较，命中车体后直接跳过原有的旋转框浮点判断。

单灯模式不建立连接遮罩。双灯模式优先使用当前帧灯板；某一灯板短暂丢失时，仅使用已确认且仍有效的预测灯板补全。连接区域内的亮点不会进入信标输出，连接区域外的双信标仍需同时保留。

真实下摄视频 `E:/Desktop/省赛车-前后2灯板/下摄-有车灯有信标1` 共 3775 帧：断裂车灯保护版双灯模式输出 2617 帧双车灯、118 帧单车灯、1040 帧无车灯；信标数量分布为 0/1/2 个分别 1641/1540/594 帧。截图中的 1703、1775、2103 帧均恢复为双车灯输出。单灯模式与旧实例逐字节零差异；独立 Release 测试中平均耗时约 0.098 ms、P99 约 0.176 ms、最大约 0.465 ms，未出现超过 20 ms 的帧。

修复要点：使用 OpenCV 离线连通域分析确认低评分但高亮、细长的第二灯板候选，然后仅在双灯模式下按核心面积、主轴长度、细长度、综合评分和峰值灰度进行恢复；最终仍需通过角度、长度比、旋转矩形不重叠和中心距约束。该离线分析只用于找出漏检样本和校准阈值，实时路径仍是无模型、确定性的 C 算法。

针对绳子把同一块车灯切成上下两个二值连通域的情况，双灯模式会在车灯候选阶段按相邻间距、方向和联合主轴重新合并断裂核心。合并后的车灯边界参与信标遮罩，因此断裂出来的上半段不会再被当作信标；单灯模式仍使用原来的严格合并条件。

在真实视频第 2622、2627 帧复核：均输出 2 车灯和 1 个画面外侧真实信标，原先位于断裂车灯上半段的 B1 不再输出。全视频更新统计为 1040 帧无车灯、118 帧单车灯、2617 帧双车灯。

## 使用

在 BeaconImageAnalyzer 中加载本目录，选择“单车灯”或“双车灯”。单灯真实视频回归和当前验证边界见 [../验证清单.md](../验证清单.md)。
