# 前后摄前后双车灯实例

本实例从 `instances_front&back/0804-张跃哲优化-fcb0e1befe4addf384e84af5142ff75f5a0fc099` 复制并做双车灯扩展，同时作为 2BL3 真机迁移的桌面回归源。真机使用相同检测逻辑但默认启用双灯模式，并通过 SPI v4 发送两个车灯。

算法 Build ID：`0x20261001`。

## 模式

- 默认是单车灯模式。该模式保持来源实例的候选选择、时序、遮罩和输出不变。
- 双车灯模式通过可选动态接口 `beacon_image_set_car_lamp_mode(2)` 启用；传入其他值恢复单车灯模式。
- 双车灯模式最多输出两个车灯。内部 `CAR0` 沿用原主目标，`CAR1` 是最佳兼容次目标；槽位只用于关联和 CSV 导出，不表示物理车头或车尾。
- 任一灯板单独可见时允许只输出一个。`CAR0` 始终跟随原算法主目标，`CAR1` 只跟随兼容次目标，不进行物理车头/车尾身份交换，从而保证槽 0 的当前结果和丢失预测均与单灯基线一致。

## 双灯配对约束

第二候选必须独立通过原车灯判定，并同时满足：

- 两灯角度差不超过 20°；
- 长度比不超过 2；
- 两个旋转框不重叠；
- 中心距离不超过较长灯板长度的 2 倍。

二值检测和灰度补充路径都会保留前两名合格候选。信标检测前同时清除两个当前/预测车灯区域，最终信标也会与两个车灯框分别互斥，避免第二灯板被当成信标。

## 车体连接遮罩

两块灯板配对成立后，算法取两个旋转灯板边界的 8 个角点构造凸包，将两灯之间的区域视为车体，不再允许输出信标。每帧只为最多 8 个点构造一次遮罩，并预计算 120 行的左右边界；二值图清除使用逐行连续内存写入，灰度候选和最终输出只增加两次整数边界比较。

单灯模式不建立车体连接遮罩，因此保持来源实例的处理路径。双灯模式下，只有当前帧同时测得两块灯板时才建立连接遮罩；某一灯板仅剩时序预测或当前帧只检测到一块灯板时，不连接两灯之间的区域，恢复原单灯遮罩方式。预测框只保留自身的窄区域排斥，不参与车体拉线。

## 使用

在 BeaconImageAnalyzer 中加载本目录，选择“单车灯”或“双车灯”。旧上位机或缺少模式接口的加载器仍可按原单灯接口使用本实例。

回归和新视频统计见 [../验证清单.md](../验证清单.md)。
