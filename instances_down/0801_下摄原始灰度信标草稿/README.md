# 下摄原始灰度信标草稿

该实例以 Air CM7_1 的 `Estimation/Pos_Est/image_down.c` 为接口基线，使用独立桌面适配层接收 188x120 Raw 图像并读取 `image_data[Center]`。当前仅用于上位机离线验证，未修改核心1固件。

当前算法 Build ID：`0x20260816`。

处理顺序：

1. 使用固定灰度阈值 200 提取车灯饱和核心，再按核心尺度生长局部自适应灰度包络，统一计算核心与包络长宽比、亮度、均匀性、背景对比度和包络面积。
2. 面积不超过32像素的断裂饱和核心只有在同方向间隔、横向偏移、联合长宽比和自适应灰度路径同时成立时才合并；合并后重新计算核心矩、方向和完整灰度包络，避免仅按几何距离误合并无关亮点。
3. 车灯和信标先独立生成灰度证据，再将中心距离不超过5像素的证据合并为同一内部目标并互斥分类。明确亮条判为车灯，紧凑且通过可靠信标规则的目标判为信标，背景嵌入或无法可靠分类的目标均不输出；只有最终车灯类目标才建立信标屏蔽区。
4. CAR0坐标和尺寸取饱和核心，信标屏蔽使用完整灰度包络。车灯选择依次比较强弱等级、是否完整可见和当前帧置信度，仅在同一可见性等级且分数接近时使用轨迹预测；只有截断候选存在时仍允许输出。信标继续使用3x3与9x9滑动窗口及局部灰度特征，normal峰值门限为195，normal/medium长宽比保留0.05像素量化容差；左右边缘仅通过weak规则的目标需要更严格的对比度、径向衰减和集中度。
5. 当 Roll、Pitch 和高度有效且模型未外推时，信标和车灯中心都必须位于下摄7米闭合边界内，并保留原有9像素安全距离；算法不使用目标外观绕过地平线裁剪，边界模型误差单独通过地平线标定解决。
6. 信标候选在 5 像素内去重，按当前帧半峰面积降序输出 B0、B1。当前帧无候选时仅 B0 预测最多 2 帧，B1 立即失效。

时序层不延迟当前帧可靠 B0/CAR0 的显示；只有同一主要目标连续命中 2 帧后才允许丢帧预测或续航，单帧目标后出现空白帧时不输出幽灵预测。

地平线求根按列复用上一列的根和内外状态；只在切线、根数变化或局部跟踪失败时回退到原完整扫描，模型参数、边界坐标和过滤语义保持不变。

上位机每个视频帧只执行一次实例的`image_down_update()`；B0/B1、CAR0、二值图和闭合边界都读取这一次执行的结果。闭合边界按`image_down_horizon_contains(..., 0)`对应的离散有效区边缘渲染，只绘制画面内真实存在的有效/无效交界；物理边界位于画面外时不会沿屏幕边框封口，也不使用另一套模型预绘、视觉插值或上一帧曲线。

算法内部仍保持原有 `image_data[Center]`、向右为正的坐标极性和车灯输出接口。桌面适配层仅在交给上位机公共渲染器时转换X极性；上位机会同时渲染闭合边界的上、下两条分支。
