# 2BL3前后摄地平线整数截止行实例

该实例以稳定候选`0x20260974`为唯一基线，只优化地平线过滤的热循环，不修改检测参数、候选规则、坐标极性、时序逻辑或输出接口。

## 结构优化

- 亮点超过512、进入普通稀疏或稠密路径时，将188列鱼眼地平线的浮点阈值预先转换为整数截止行。
- 亮点不超过512的极稀疏帧继续使用旧判断，避免预计算固定开销拖慢简单画面。
- 原来每个亮点都执行的整数转浮点、容差减法和浮点比较，改为一次整数行号比较。
- 截止行使用与原谓词严格等价的向上取整；无效地平线和无效列继续放行，NaN和画面下方阈值继续拒绝画面内像素。
- 地平线参数、2像素容差、峰值响应、候选分类和最终B0/B1、CAR0结果均保持不变。
- 不增加动态内存、位置特判、光照特调或视频专用参数。

算法Build ID为`0x20260975`。

## 验证结果

- 使用前摄、后摄、水平和大姿态四组有效遥测，对4段视频共15991帧完成基线标量、新标量、基线CM4 DSP语义、新CM4 DSP语义及交叉对拍，全部零差异。
- 纯负样本视频整段2455帧零差异，因此637～2430帧误检集合保持不变。
- GCC严格告警编译通过，标量和DSP动态库均导出Build ID `0x20260975`。
- CM4软浮点交叉编译后，`find_beacons`由11520字节缩至10740字节；普通稀疏热循环改为整数比较，原浮点路径仅为极稀疏门控保留。
- PC使用硬件浮点，交替性能结果受噪声影响且不代表160 MHz CM4；预计板端复杂帧可减少约0.7～1.5 ms，需在用户确认回放后移植并以DWT实测。
